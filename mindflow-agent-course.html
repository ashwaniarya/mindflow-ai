    Lesson 1 · 12 min

    One model call, then structured output

    Everything an agent does is made of single model calls. Get the shape of one call exact, and the rest is plumbing.

    Goal. Make one call to Gemini from the browser, then force the answer into JSON you can trust.

    The call

    A model call is a function. Text goes in, text comes out, and the model remembers nothing afterwards. MindFlow uses the @google/genai SDK. This is the smallest useful call in the project:

    services/geminiService.ts
    const ai = new GoogleGenAI({ apiKey });

const response = await ai.models.generateContent({
  model: "gemini-3-flash-preview",
  contents: `Generate 4 concise sub-topics for the mind map node: "${topic}".`,
});
console.log(response.text);   // free-form prose. Useless to a program.

    Structured output

    Prose is fine for a human and useless for code. Ask for JSON and give the SDK a response schema, and you get an array you can loop over:

    const response = await ai.models.generateContent({
  model: "gemini-3-flash-preview",
  contents: `Generate 4 concise sub-topics for: "${topic}". Keep them 1-3 words.`,
  config: {
    responseMimeType: "application/json",
    responseSchema: { type: Type.ARRAY, items: { type: Type.STRING } },
  },
});
const subTopics = JSON.parse(response.text || "[]");
    Structured output is the foundation of every "AI feature" that looks like magic in a product: a schema plus a parse. The generation is the easy part. The contract is the work.

    Why this is not an agent yet

    The call has no way to look at the map, no way to decide what to do next, and no way to act twice. It answers once. Chain two of these calls and you have a pipeline. That is what MindFlow was before this week: draft branches, then expand them, always in that order. Useful, honest, and not an agent.

    Trap. The key is inlined into the browser bundle by Vite's define. Anyone can read it from the deployed JS. That is why the public demo ships without a key and why lesson 5 exists.

    Try it

    1. Create .env.local with GEMINI_API_KEY=... and restart Vite.
    2. Right-click a node, choose "Expand with AI". That path calls generateSubTopics. Compare the labels with demo mode.
    3. Break the schema on purpose: change Type.ARRAY to Type.OBJECT. Watch what JSON.parse gives you. Put it back.

    What does the model keep between two generateContent calls?

    Nothing. Any memory is something your code passes back in on the next call. Lesson 3 builds exactly that.

    Why ask for a response schema?

    The model is the same. The schema turns prose into data your program can rely on.

    Lesson 2 · 15 min

    LangGraph: state, nodes, edges, streaming

    LangGraph is a small idea with a big payoff: your program is a graph, and a typed state object flows through it.

    Goal. Rebuild the original two-step pipeline as a LangGraph graph and stream its steps to the console.

    Four words

    WordMeaningIn MindFlow
    StateOne object every step reads and writes. Declared with Annotation.Root.topic, nodes, edges, history, pendingCalls, log, steps
    ReducerHow a step's output merges into state. Concat, overwrite, or custom.log concats, nodes overwrites
    NodeA function: state in, partial state out.agent, tools
    EdgeWhat runs next. Fixed, or conditional on state.tools → agent always; agent → tools | END decided by a function

    Declaring state

    Each field says how updates merge. This is the part people skip and then wonder why nodes disappear.

    services/reactAgent.ts
    export const AgentState = Annotation.Root({
  topic: Annotation<string>(),
  nodes: Annotation<MindMapNode[]>({ reducer: (_s, u) => u, default: () => [] }),   // overwrite
  edges: Annotation<Edge[]>({ reducer: (_s, u) => u, default: () => [] }),
  history: Annotation<Content[]>({ reducer: (s, u) => s.concat(u), default: () => [] }), // append
  pendingCalls: Annotation<ToolCall[]>({ reducer: (_s, u) => u, default: () => [] }),
  log: Annotation<string[]>({ reducer: (s, u) => s.concat(u), default: () => [] }),
  steps: Annotation<number>({ reducer: (_s, u) => u, default: () => 0 }),
});

    The pipeline version, for contrast

    This is the graph MindFlow shipped with originally. Two nodes, a straight line. Read it once so the loop in lesson 4 feels like the small change it is.

    const workflow = new StateGraph(GraphState)
  .addNode("draftInitial", draftInitial)   // one model call: root + branches
  .addNode("expandLeaves", expandLeaves)   // one model call: sub-topics for every branch
  .addEdge(START, "draftInitial")
  .addEdge("draftInitial", "expandLeaves")
  .addEdge("expandLeaves", END);
export const mindMapAgent = workflow.compile();

    Streaming

    stream() yields once per completed node, as an object keyed by the node's name. The UI does not wait for the whole graph. It paints after every step.

    const stream = await graph.stream({ topic });
for await (const chunk of stream) {
  // chunk = { agent: {...partial state} }  or  { tools: {...partial state} }
  for (const [nodeName, output] of Object.entries(chunk)) paint(output);
}
    A reducer is a design decision, not boilerplate. nodes overwrites because the tools step returns the whole map. log concats because reasoning lines are a transcript. Pick the wrong one and you either lose nodes or duplicate them.

    Try it

    1. The retired pipeline file is gone from the project, and there is no repo to recover it from. Use the snippet above instead: count its nodes and edges, then count them in reactAgent.ts. The whole difference is one conditional edge and one cycle.
    2. In reactAgent.ts, change the log reducer to overwrite ((_s, u) => u). Run a generation. The status pill still works, but state.log now holds one line. Put it back.
    3. Add console.log(Object.keys(chunk)) inside the stream loop in MindMap.tsx. Watch the alternation: agent, tools, agent, tools.

    Which reducer should nodes use if the tools step returns the full map every time?

    Overwrite. Concat would duplicate every node on every step and the canvas would have to dedupe.

    What does one iteration of for await (const chunk of stream) represent?

    One completed node. That is the granularity the canvas repaints at.

    Lesson 3 · 15 min

    Tools: the map is the tool surface

    A tool is a function the model can ask for by name. Your code runs it and sends the result back. That round trip is the atom of every agent.

    Goal. Declare four tools, execute a call the model makes, and feed the result back into the conversation.

    The round trip

    Declaring a tool

    A function declaration is a contract written for the model. Write the description like documentation for a sharp junior: what it does, what it returns, when to use it.

    services/reactAgent.ts
    {
  name: 'expand',
  description: 'Add 2 to 4 short sub-topics under an existing branch.',
  parameters: {
    type: Type.OBJECT,
    properties: {
      branch_label: { type: Type.STRING },
      subtopics: { type: Type.ARRAY, items: { type: Type.STRING } },
    },
    required: ['branch_label', 'subtopics'],
  },
}

    Executing a call

    The model returns functionCalls. Your code matches on the name, runs real logic against real state, and returns a short string. Short matters: the result goes back into the prompt on every later round.

    case 'expand': {
  const parent = findNode(nodes, String(args.branch_label ?? ''));
  if (!parent) return { nodes, edges, result: `No node matches "${args.branch_label}". ${summarize(nodes, edges)}` };
  subtopics.forEach((label, index) => {
    const id = getId();
    nodes.push({ id, type: 'custom', position: {...}, data: { label, color: parent.data.color } });
    edges.push({ id: `e-${parent.id}-${id}`, source: parent.id, target: id, ... });
  });
  return { nodes, edges, result: `Expanded "${plain(parent.data.label)}" with ${subtopics.length} sub-topics.` };
}
    Notice the failure case returns a helpful message plus a map summary, and does not throw. The model reads "No node matches" and corrects itself on the next round. A thrown error would end the loop.

    Closing the loop on memory

    Lesson 1 said the model remembers nothing. Tools are where that bites. After executing, you append a functionResponse turn to history so the next call sees what happened:

    responses.push({ role: 'user', parts: [{ functionResponse: { name: call.name, response: { result: outcome.result } } }] });
    Design rule. Four tools, small results, one summary tool. Every extra tool is a way for the model to be wrong; every long result is tokens re-read on every round. inspect_map returns branch names and child counts, never full labels or positions.

    Try it

    1. Add a fifth tool, remove_branch({label}). Declare it, handle it in runTool, and return a one-line result.
    2. Make summarize return every node's position too. Generate once with a key and watch the prompt size in the console. Then revert.
    3. Rename expand's description to something vague like "does stuff". Generate three maps. Count how often the model calls it wrongly.

    What does the model see about a tool?

    Only the declaration. The description is the whole interface. Write it like docs.

    A tool call fails because the branch label does not exist. Best response?

    Return context. The next reasoning step reads it and self-corrects. Throwing ends the graph; ignoring hides the mistake.

    Lesson 4 · 18 min

    The ReAct loop: reason, act, observe, repeat

    Take the graph from lesson 2, the tools from lesson 3, add one conditional edge and one cycle. That is the whole agent.

    Goal. Wire agent → tools → agent with an exit condition and a step budget, and read every line of the graph definition with confidence.

    The definition

    services/reactAgent.ts, bottom
    const shouldContinue = (state: State) =>
  (state.pendingCalls.length > 0 && state.steps < MAX_STEPS ? 'tools' : END);

export const mindMapReactAgent = new StateGraph(AgentState)
  .addNode('agent', agentNode)
  .addNode('tools', toolsNode)
  .addEdge(START, 'agent')
  .addConditionalEdges('agent', shouldContinue, { tools: 'tools', [END]: END })
  .addEdge('tools', 'agent')     // the cycle
  .compile();

    Read shouldContinue aloud: "if the model asked for tools and we have budget, run tools; otherwise stop." That one function is the difference between an agent and a pipeline. ReAct is a name for exactly this shape: Reason (agent node), Act (tools node), observe (the function responses in history), repeat.

    The agent node

    Two responsibilities: call the model with everything so far, and translate the answer into either tool calls or "done".

    async function agentNode(state: State) {
  if (!apiKey) { ... }                                         // demo planner, lesson 5
  const history = state.history.length ? state.history : [{ role: 'user', parts: [{ text: `Build a mind map about: "${state.topic}".` }] }];
  const response = await ai.models.generateContent({
    model: MODEL, contents: history,
    config: { systemInstruction, tools: [{ functionDeclarations }] },
  });
  const calls = (response.functionCalls ?? []).map(c => ({ name: c.name, args: c.args ?? {} }));
  const thought = response.text?.trim();                       // the model's own words, when it wrote any
  return {
    history: [...(state.history.length ? [] : history), ...(modelContent ? [modelContent] : [])],
    pendingCalls: calls,                                     // empty array = the model chose to stop
    log: [thought ? `Reason: ${thought}` : calls.length ? `Reason: calling ${calls.map(describe).join(', ')}` : 'Reason: done'],
  };
}

    The tools node

    function toolsNode(state: State) {
  let nodes = state.nodes, edges = state.edges;
  const responses = [], log = [];
  for (const call of state.pendingCalls) {
    const outcome = runTool(call, { ...state, nodes, edges });
    nodes = outcome.nodes; edges = outcome.edges;
    log.push(`Act: ${describe(call)} -> ${outcome.result.split('\n')[0]}`);
    responses.push({ role: 'user', parts: [{ functionResponse: { name: call.name, response: { result: outcome.result } } }] });
  }
  return { nodes, edges, history: apiKey ? responses : [], log, pendingCalls: [], steps: state.steps + 1 };
}

    Guardrails, and why each exists

    GuardWhereFailure it prevents
    Step budget MAX_STEPS = 10shouldContinueAn endless loop that bills forever
    "Never call inspect_map twice in a row"system instructionReading without acting, the most common agent stall
    "Do not add more than 5 branches"system instructionA map that grows past what the canvas can lay out
    Tool errors return text, never throwrunToolOne bad label ending the whole run
    History always starts with a user turnagentNodeAPI rejects a conversation that starts with a model turn
    Prompt rules are soft. Code rules are hard. The step budget is code because it protects money. The inspect rule is prompt because a violation only costs one round.

    Try it

    1. Set MAX_STEPS = 2. Generate. The map stops after the branches, and the pill says nothing about failure. Decide whether that silence is acceptable. Then restore 10.
    2. Remove the [END]: END mapping. Read the error LangGraph throws. It is telling you a conditional edge must name every outcome.
    3. Move the "no more than 5 branches" rule from the prompt into runTool as a hard cap. Which version would you ship? Why?

    What ends the loop when the model is satisfied?

    No function calls. pendingCalls is empty, shouldContinue returns END. The budget is the backstop, not the normal exit.

    Which of these makes a LangGraph graph an agent rather than a pipeline?

    The cycle. Pipelines have state and can stream too. Only the loop lets the model decide how many steps to take.

    Why does the step budget live in code instead of the prompt?

    Anything that protects money or safety must be enforced where the model cannot override it.

    Lesson 5 · 10 min

    Demo mode: the same loop without a key

    A public demo cannot ship an API key. The answer is not to fake the output. It is to fake the decision-maker and keep everything else real.

    Goal. Understand the scripted planner and why it runs through the identical graph, tools, and reducers as the live model.

    Swap the brain, keep the body

    The agent node has one branch at the top. With no key, a deterministic function decides which tool to call from the state. Everything downstream, the tools node, the history, the streaming, the canvas, does not know the difference.

    services/reactAgent.ts
    const scriptedPlanner = (state: State): ToolCall[] => {
  const root = state.nodes.find(n => n.data.isRoot);
  if (state.steps === 0) return [{ name: 'inspect_map', args: {} }];          // look first
  if (!root) {
    const draft = demoDraft(state.topic);                                   // curated or generic branches
    return [{ name: 'add_branches', args: { root_label: draft.rootLabel, labels: draft.branches } }];
  }
  const branches = state.edges.filter(e => e.source === root.id).map(...);   // the root's children
  const thin = branches.find(b => !state.edges.some(e => e.source === b.id)); // a branch with no children
  if (thin) return [{ name: 'expand', args: { branch_label: thin.data.label, subtopics: ... } }];
  return [];                                                                // nothing thin left: done
};

    Read the shape: it is the same policy the prompt asks the model to follow. Inspect, draft, expand every thin branch, stop. When you later compare live runs against demo runs, differences point at the model, not at your plumbing.

    Curated content beats lorem

    demoContent.ts holds four hand-written maps (SEO Visibility, Lateral Design Processes, Engineering, Design and Art, and Pixel Colour Change via Sound Waves) with keyword matching, plus a generic fallback. Demo content is design work. A visitor judges the product by the first map they see.

    Trap. The demo planner adds a 400 ms pause per step so the loop is visible. Never leave a pause like that in the live path; there the model's latency is the pacing.

    Try it

    1. Add a fifth curated map about something you care about. Give it four branches and three sub-topics each. Add keywords. Generate it by typing one of the keywords.
    2. Make the planner call rename once before finishing, turning the root label into title case. The live model may do this on its own; now demo mode does too.

    What does demo mode replace?

    Only the decision. The graph, tools, reducers, and streaming are shared, which is what makes the demo an honest demo.

    Lesson 6 · 15 min

    Canvas: streaming into React Flow

    This is the design-engineering half. The agent produces state; the canvas has to make it feel alive, legible, and yours to edit.

    Goal. Trace one graph step from the stream to pixels, then see how extend-selection, colour prediction, and Smart Align reuse the same primitives.

    From chunk to pixels

    components/MindMap.tsx
    const stream = await mindMapReactAgent.stream({ topic });
for await (const chunk of stream) {
  for (const [, output] of Object.entries(chunk)) {
    const latest = output.log?.[output.log.length - 1];
    if (latest) window.dispatchEvent(new CustomEvent('mindmap:agent-progress', { detail: { progress: latest } }));
    // last write of an id wins, which is what a rename needs
    if (output.nodes) setNodes(nds => [...new Map([...nds, ...output.nodes].map(n => [n.id, n])).values()]);
    if (output.edges) setEdges(eds => [...new Map([...eds, ...output.edges].map(e => [e.id, e])).values()]);
    setTimeout(() => fitView({ padding: 0.2, duration: 800 }), 50);
  }
}

    Components talk through window events (mindmap:agent-progress, mindmap:selection, mindmap:save-map). It is a deliberate trade: no shared store, and any component can listen. It stops scaling around ten event names. MindFlow has eight.

    Three features, one pattern

    Extend a selectionReact Flow's onSelectionChange broadcasts the selected node. The composer flips to "Extend". Generate calls generateSubTopics(label, guidance) and stacks children under existing ones.
    Predicted colourpredictColor(label, index) maps keywords to a palette. Branch nodes get it, children and edges inherit it, the minimap reads it. Rendered as a 3px left border and a 7% tint.
    Smart AlignsmartAlign(nodes, edges) is a tidy-tree: subtree height from measured node sizes, parent centred on its children. Runs after every generation and on the button.

    Smart Align, the core

    services/layout.ts
    const measure = (id) => {                          // height of a subtree
  const kids = children.get(id) ?? [];
  const stacked = kids.reduce((sum, kid) => sum + measure(kid), 0) + rowGap * Math.max(0, kids.length - 1);
  return Math.max(nodeHeight(byId.get(id)), stacked);
};
const place = (id, x, top) => {                    // parent centred on its children
  positions.set(id, { x, y: top + (measure(id) - nodeHeight(node)) / 2 });
  let cursor = top;
  for (const kid of children.get(id) ?? []) { place(kid, x + nodeWidth(node) + columnGap, cursor); cursor += measure(kid) + rowGap; }
};
    Measured sizes (node.width, node.height) come from React Flow after the first render. That is why the layout runs in a setTimeout after nodes exist, not in the same tick they were added.

    Try it

    1. Change columnGap to 40 and rowGap to 8. Click Smart Align. Feel why the defaults are 120 and 28.
    2. Add a keyword pair to colorHints for your own domain, then generate a map that uses it.
    3. Double-click a node, type markdown with a bullet list, press Escape. Then Smart Align: the taller node pushes its siblings apart because the layout measures real height.

    Why does the canvas dedupe nodes by id on every chunk?

    Full map per step plus a Map keyed by id means the latest version of a node wins, which is what a rename needs.

    The last skill is honesty under questioning. Know what you built, what you did not, and what you would do next.

    Goal. Reproduce the deploy, verify the live build, and rehearse five interview answers.

    Say it right

    They askYou say
    Is this an agent?Yes: a ReAct loop in LangGraph. An agent node reasons and picks tools, a tools node acts on the map, a conditional edge loops until the model stops calling tools or hits a step budget of 10.
    What were the tools?Four: inspect_map, add_branches, expand, rename. The map is the tool surface. Results are short summaries so every round stays cheap.
    How does the demo work without a key?A scripted planner replaces only the decision inside the agent node. Same graph, tools, reducers, and streaming. Keys never ship in a browser bundle.
    What would you change?Move the model call behind a small server so the key is private and rate-limited. Add a merge tool. Persist maps server-side instead of localStorage.
    What was the hardest part?Layout. Streaming nodes in arbitrary order fought the canvas until Smart Align used measured node sizes and ran after each step.
    Do not say "it uses AI to build mind maps". Say what loops, what decides, what is bounded. Specific beats impressive.
